# Unnamed Tracking Playnite Plugin

Playnite 10 generic plugin for synchronizing a Playnite library with the Unnamed Tracking application.

The plugin uses Unnamed Tracking's normal user API-key authentication and the game's playnite_guid field to keep Playnite entries associated with their server-side games.

## What it does

- Configures the Unnamed Tracking server URL and API key from Playnite's extension settings.
- Tests the configured connection against the authenticated game API.
- Manually synchronizes the complete Playnite library.
- Synchronizes only selected games from the Playnite game context menu.
- Creates new games in Unnamed Tracking and updates existing games.
- Matches existing games by the generated Playnite folder location and then by playnite_guid, so renaming a Playnite game does not create a duplicate.
- Sends Playnite metadata including title, sort title, description, release date, developer, publisher, series, tags, features, links, source, age rating, favourite state, notes, playtime, rating and completion status.
- Uploads Playnite cover and banner artwork when it is available.
- Reports artwork failures as warnings instead of incorrectly treating a successful game synchronization as a failed game.
- Optionally synchronizes the whole library when Playnite starts.
- Optionally updates already-linked games when a game stops.
- Skips games carrying the configurable ignore tag (default `trackingapp_ignore`).
- Provides a synchronization preview that shows creates, updates, and ignored games without changing the server.
- Shows manual sync progress and supports cancelling an in-progress library synchronization.
- Produces detailed extension logs for HTTP requests, responses and synchronization failures.

## Requirements

- Windows
- Playnite 10.x
- .NET Framework 4.6.2 developer targeting support for local development
- An Unnamed Tracking user API key beginning with utk_

Playnite's plugin SDK targets .NET Framework 4.6.2 for the Playnite 10 plugin model. The project references the Playnite SDK through NuGet and does not reference Playnite's private/non-SDK assemblies.

## Configure

1. Install the generated .pext package in Playnite, or add the Release output directory to Settings → For developers → External extensions while developing.
2. Open Add-ons → Extension settings → Unnamed Tracking.
3. Enter the base URL of the Unnamed Tracking server.
4. Enter a user API key generated by the Unnamed Tracking application.
5. Click Test connection.
6. Use Upload Playnite Library for an initial synchronization.
7. Optionally configure the ignore tag and enable startup synchronization and/or synchronization after a game stops.
8. Use Preview sync to inspect what would be created, updated, or ignored before uploading.
9. Use Cancel while a manual library sync is running if you need to stop it.

The API key is stored by Playnite with the extension settings. Treat the Playnite profile as sensitive configuration and do not commit or share the generated settings file.

## Synchronization behaviour

### Initial/manual synchronization

The plugin reads the current Playnite library and compares each game with the authenticated Unnamed Tracking account.

Existing games are matched using:

1. folder_location, which is generated as playnite-<safe-name>-<Playnite GUID>.
2. playnite_guid as a fallback.

New games are created through /api/game/create. Existing games are updated through /api/game/update/{id}.

### Artwork

Cover and banner artwork are uploaded to:

- /api/game/{id}/assets/key_art
- /api/game/{id}/assets/banner

Playnite can store artwork as local library files or remote URLs. The plugin handles both forms where possible.

### Game-stopped synchronization

When enabled, stopping a game updates the already-linked Unnamed Tracking game with the current Playnite playtime, favourite state and completion status. It deliberately does not create missing games; use a library synchronization first.

### Ignored games

Games carrying the configured ignore tag are skipped completely. The default tag is `trackingapp_ignore`; clear the setting to disable this filter. The comparison is case-insensitive.

### Synchronization preview

The Preview sync action reads the authenticated remote library and compares it with Playnite without creating, updating, or uploading artwork. It reports the games that would be created, updated, or ignored.

### Progress and cancellation

Manual library synchronization reports per-game progress and can be cancelled. Cancellation stops further game operations after the current network operation finishes.

### Automatic startup synchronization

When enabled, the plugin snapshots the Playnite library on the Playnite application thread and performs the network synchronization asynchronously. This prevents network operations from blocking Playnite's UI.

## API contract

The plugin currently relies on these authenticated Unnamed Tracking endpoints:

- GET /api/game/list
- POST /api/game/create
- PATCH /api/game/update/{game_id}
- POST /api/game/{game_id}/assets/{asset_kind}

Authentication is sent as:

Authorization: Bearer utk_<secret>

These endpoints are part of the Unnamed Tracking application's user-authenticated game API.

## Build

From PowerShell:

dotnet restore UnnamedTrackingPlaynite.sln
dotnet build UnnamedTrackingPlaynite.sln --configuration Release

The extension output is:

src/UnnamedTrackingPlaynite/bin/Release/net462/

It must contain the plugin assembly and extension.yaml.

## Package

If Playnite Toolbox is installed:

./pack.ps1

The GitHub Actions PEXT workflow also creates a .pext artifact from the Release assembly and manifest.

A .pext package is a ZIP-format extension package containing:

- UnnamedTrackingPlaynite.dll
- extension.yaml

## CI

The repository keeps the CI surface deliberately small:

- Build plugin — restores and builds the solution and validates the extension output. This is the primary CI build check.
- Build Playnite extension — packages the release output as a `.pext` artifact and publishes a GitHub release when changes reach `main` (or a `v*` tag is pushed).

The previous Playnite runtime smoke-test workflows were removed because they depended on assumptions about the hosted runner and Playnite's portable runtime/log layout that are not reliable CI guarantees. The extension has been exercised successfully in a real Playnite installation.

## Troubleshooting

### The extension appears in Playnite but synchronization does nothing

Open the extension settings and use Test connection. Also verify that the API key starts with utk_ and belongs to the same Unnamed Tracking account that should receive the library.

### A game is duplicated

Run another synchronization after the latest plugin version. The plugin uses the Playnite GUID as a stable association and sends it as playnite_guid.

### Artwork fails but games synchronize

Check the extension log for the individual artwork request. Artwork is intentionally a warning: metadata and game state remain synchronized even when an image cannot be read or uploaded.

### A startup synchronization is slow

The initial synchronization is intentionally per-game and may upload two artwork assets for each game. It runs asynchronously so Playnite's UI is not blocked. Use Preview sync before a large initial upload, and Cancel if a manual sync needs to stop.

### Finding logs

Playnite records extension logging separately from the main application log. The plugin writes request IDs, endpoints, response status and synchronization errors to its extension logger.

## Development

Playnite's SDK is not fully thread-safe. Code that reads Playnite database objects is kept on the Playnite event/UI thread and the resulting data is then used by asynchronous network operations.

Do not add references to Playnite's private assemblies such as Playnite.dll or Playnite.Common.dll. Playnite's extension system requires plugins to use the SDK surface.

## Compatibility

This project currently targets the Playnite 10 plugin model (net462 / Playnite SDK). Playnite's newer extension runtime should be treated as a separate compatibility target rather than silently changing the runtime of this plugin.
